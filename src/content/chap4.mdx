## 1. そもそも「CTest」と「GoogleTest」は何が違うのか？

初心者が最もつまずきやすいのが、「どちらを使えばいいのか？」という疑問です。  
結論から言うと、**「GoogleTestで中身の合否を判定し、CTestで外側から束ねて一括実行する（二人三脚）」** のが正解です。

### 🏢 たとえで理解する「審判員」と「大会マネージャー」

* **GoogleTest（gtest）＝「個別競技の審判員」**  
  C++のコードの中に潜り込み、「この関数の計算結果は `45.23` と一致しているか？」「例外が正しく発生したか？」など、**関数やクラス単位の合否を判定するフレームワーク**です。
* **CTest ＝「大会の運営マネージャー」**  
  プロジェクト内に作られた複数のテスト用実行ファイル（陸上、水泳、柔道のように分かれたテストバイナリやPythonスクリプト）を、**1コマンドで一括並列実行し、全体の合否サマリーを集計するランナー**です。

```
【CTest (大会運営マネージャー)】
  $ ctest --output-on-failure
  ├── ▶ sonar_test   (GoogleTest製バイナリ) ───> 審判員: EXPECT_NEAR判定 [PASS]
  ├── ▶ network_test (GoogleTest製バイナリ) ───> 審判員: EXPECT_EQ判定   [PASS]
  └── ▶ e2e_test.py  (Pythonスクリプト)     ───> 審判員: pytest判定      [PASS]
  ──────────────────────────────────────────────────────────
  結果サマリー: 100% tests passed, 0 tests failed! (終了コード: 0)
```

### 📊 決定的な違いの比較表

| 比較項目 | GoogleTest (gtest) | CTest |
| :--- | :--- | :--- |
| **ツールの分類** | **テストフレームワーク** | **テストランナー（実行管理ツール）** |
| **提供元** | Google製（外部C++ライブラリ） | Kitware製（CMakeに標準付属） |
| **書く場所** | C++のソースコード（`TEST()`, `EXPECT_EQ()` 等） | `CMakeLists.txt` の設定（`enable_testing()`, `add_test()`） |
| **検証する粒度** | 関数、クラス、境界値、浮動小数点の丸め誤差 | 実行ファイル（`.exe`）、Pythonテスト、シェルスクリプト全体 |
| **直接叩くコマンド** | `./build/tests/sonar_test`（単体バイナリ直接） | `ctest --test-dir build`（全テスト一括実行） |

> 💡 **実務での使い分け**  
> * **今直している関数だけ集中デバッグしたい時** ➔ `./build/tests/sonar_test` でGoogleTestを直接素早く回す。  
> * **コミット前やCI（GitHub Actions）で全件自動検証したい時** ➔ `ctest` で全テストを一斉に回す。

この関係を理解した上で、いよいよC++コードの中で審判員となる **GoogleTestの具体的な書き方** を学んでいきましょう！

## 2. GoogleTestの基本構造（TESTマクロ）

まずは、単純なテストを書いてみましょう。`TEST(テストグループ名, テストケース名)` というマクロを使います。

```cpp
#include <gtest/gtest.h>
#include "sonar_filter.hpp"

// 基本的なテストの例
TEST(SonarFilterTest, Initialization) {
    SonarFilter filter(60.0); // カットオフ周波数 60Hzで初期化
    EXPECT_EQ(filter.GetCutoffFrequency(), 60.0);
}
```

## 3. 数理ロジックのテスト（浮動小数点の比較）

数値計算のテストにおいて、`EXPECT_EQ`（完全一致）で `double` や `float` の計算結果を比較してはいけません。丸め誤差によってテストが落ちるからです。
代わりに **`EXPECT_NEAR`** または **`EXPECT_DOUBLE_EQ`** を使用します。

```cpp
TEST(SonarFilterTest, SignalAttenuation) {
    SonarFilter filter(60.0);
    
    // 入力信号
    double input_signal = 100.0;
    
    // フィルタ処理実行
    double output_signal = filter.Process(input_signal);
    
    // 期待値（理論計算による減衰後の値）
    double expected_output = 45.23;
    
    // 誤差 0.01 以内であれば合格とする
    EXPECT_NEAR(output_signal, expected_output, 0.01);
}
```

> ⚠️ **テストしにくいコードに注意**  
> もしあなたのC++コードが、「ファイルから直接データを読み込み、内部で計算し、直接ファイルに書き出す」ような設計（密結合）になっていると、単体テストが非常に困難です。  
> 計算ロジック（`Process`関数など）は、メモリ上の配列や値を受け取って返すだけの「純粋な関数・クラス」に分離（疎結合化）するよう心がけましょう。
