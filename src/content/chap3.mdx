## 1. 「ライブラリ」と「テスト」を分離する

テストしやすい設計の第一歩は、`main()` 関数を持つ実行ファイルにすべての処理を書かないことです。
コアとなる数理ロジックは**ライブラリ（.a や .so）**としてビルドし、テスト用の実行ファイルからそれをリンク（結合）して呼び出します。

## 2. 実務で使える CMakeLists.txt

プロジェクトのルートに配置する `CMakeLists.txt` のテンプレートを見てみましょう。

```cmake
cmake_minimum_required(VERSION 3.14)
project(SonarAutomationLab CXX)

# C++17規格を要求
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# ---------------------------------------------------
# 1. プロダクトコード（コアロジック）のビルド
# ---------------------------------------------------
# 信号処理ロジックなどを静的ライブラリとしてまとめる
add_library(sonar_core
    src/sonar_filter.cpp
    src/math_utils.cpp
)
target_include_directories(sonar_core PUBLIC include)

# ---------------------------------------------------
# 2. テストの有効化とビルド
# ---------------------------------------------------
enable_testing() # CTestの有効化

# テスト用実行ファイルの定義
add_executable(sonar_test
    tests/test_sonar_filter.cpp
)

# コアライブラリとGoogleTestをリンク
target_link_libraries(sonar_test
    PRIVATE sonar_core
    PRIVATE gtest gtest_main pthread
)

# CTestにテストを登録
add_test(NAME UnitTests COMMAND sonar_test)
```

> [!IMPORTANT]
> **CTestの威力**
> `enable_testing()` と `add_test()` を記述することで、ビルド後にコマンドラインから `ctest` と打つだけで、登録したすべてのテストバイナリを一括実行し、成功・失敗のサマリーを出力してくれます。これは後のCI連携（第10章）で非常に強力な武器になります。
