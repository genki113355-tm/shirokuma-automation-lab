## 1. AddressSanitizer (ASan) の導入

現代のC++開発において、メモリエラーの検出にはGCC/Clangに標準搭載されている **AddressSanitizer (ASan)** を使うのが定石です。CMakeの設定に以下の数行を足すだけで、魔法のようにメモリエラーを検知してくれます。

```cmake
# CMakeLists.txt に追記（デバッグビルド時のみ有効化）
# ※「sonar_core」は第3章で作成したプロジェクト固有の自作ライブラリ名です
if(CMAKE_BUILD_TYPE STREQUAL "Debug")
    # コンパイルオプション
    target_compile_options(sonar_core PUBLIC -fsanitize=address -g)
    # リンクオプション
    target_link_options(sonar_core PUBLIC -fsanitize=address)
endif()
```

## 2. 劇的なデバッグ体験の変化

この状態でビルドして pytest を実行すると、もしC++側で「配列の範囲外アクセス」や「解放済みメモリの使用（Use-after-free）」が発生した場合、ただ「セグフォ」と出るだけでなく、**ソースコードの何行目で発生したかという詳細なスタックトレース**を出力した上で、即座にエラーコードを返して終了します。

> ⚠️ **注意：Valgrind との使い分け**  
> AddressSanitizerはコンパイル時にコードを埋め込むため非常に高速ですが、再ビルドが必要です。  
> 一方、レガシーな巨大プロジェクトなどで再ビルドが難しい場合は、バイナリをそのまま解析できる `valgrind --leak-check=full ./sonar_test` を使用する手もあります。現代的な開発ではASanが主流です。
